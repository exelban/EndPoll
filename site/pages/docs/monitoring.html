Start with the Docker installation guide if EndPoll is not running yet. The following examples go in config.yaml. Keep one top-level hosts list and add each service beneath it.

Monitor websites and HTTP APIs

Use an HTTP or HTTPS URL for each endpoint. Set the expected response code and, optionally, an exact response body. Per-host settings override the global interval and timeout.

interval: 30s
timeout: 10s
failureThreshold: 2
successThreshold: 1

hosts:
  - name: Website
    url: https://example.com
    conditions:
      code: [200]
  - name: API health
    url: https://api.example.com/health
    interval: 15s
    timeout: 5s
    conditions:
      code: [200]
      body: "ok"
    headers:
      Authorization: "Bearer replace-with-your-token"

The failureThreshold controls how many consecutive failures are needed to mark a host down. The successThreshold controls recovery. These settings help avoid status changes caused by a single transient failure.

HTTPS checks also collect TLS certificate expiry information. A host's detail page shows response-time history and HTTP timing details such as DNS lookup, connection, TLS handshake, and time to first byte.

Monitor MongoDB, Redis, PostgreSQL, and MySQL

EndPoll detects the check type from the connection URL. Use credentials with only the access required for monitoring, and replace the sample hostnames with addresses reachable from the EndPoll container.

hosts:
  - name: MongoDB
    url: mongodb://monitor:password@mongo.internal:27017
  - name: Redis
    url: redis://:password@redis.internal:6379/0
  - name: PostgreSQL
    url: postgres://monitor:password@postgres.internal:5432/app?sslmode=require
  - name: MySQL
    url: mysql://monitor:password@mysql.internal:3306/app

MongoDB checks connect and ping the database. Redis checks authenticate when credentials are present, select the configured database, and send PING. PostgreSQL and MySQL checks connect and run SELECT 1. Redis also supports TLS with a rediss:// URL.

Connection passwords containing URL-reserved characters must be percent-encoded. Inside a container, localhost refers to that container; use a shared Docker network and the database service name when both services run in Docker.

Check TCP ports, DNS, and ICMP

hosts:
  - name: Internal TCP service
    url: tcp://service.internal:9000
  - name: Website DNS
    url: dns://example.com
    dns:
      type: A
      resolver: "1.1.1.1:53"
  - name: Router
    url: 192.168.1.1

A TCP check opens a connection to the specified port. DNS checks resolve records of type A, AAAA, CNAME, MX, NS, or TXT; add an expect list under dns to require specific values in the answer. An IPv4 address without a scheme uses ICMP ping.

ICMP checks on Linux require the NET_RAW capability, which Docker normally grants. If you have removed that capability, restore it for the EndPoll container to use ping checks.

Group related services

Use the same group value to combine related hosts on the dashboard. A grouped host with hidden: true still contributes to the group status while staying out of the group view.

hosts:
  - name: API
    url: https://api.example.com/health
    group: Application
  - name: Database
    url: tcp://postgres.internal:5432
    group: Application
    hidden: true

Connect Prometheus, Grafana, and the JSON API

EndPoll exposes Prometheus metrics at /metrics. Add your EndPoll server as a scrape target, then use that Prometheus data source in Grafana:

scrape_configs:
  - job_name: endpoll
    scrape_interval: 30s
    static_configs:
      - targets: ["endpoll:8822"]

Replace endpoll:8822 with an address reachable from Prometheus. If ui.basicAuth is enabled, configure basic_auth in the scrape job too.

  • endpoll_host_up: 1 for up, 0 for down or degraded; absent while status is unknown.
  • endpoll_host_response_seconds: duration of the latest check.
  • endpoll_host_uptime_ratio: uptime over the last 90 days, from 0 to 1.
  • endpoll_host_ssl_expiry_timestamp_seconds: certificate expiry time for HTTPS hosts.

For custom integrations, request /api/hosts for overall and per-host status, /api/hosts/{id} for host details, or /api/incidents for recent incidents. These endpoints use the same basic authentication as the dashboard when enabled.
