1. Create your monitoring configuration

Install Docker on a Linux amd64 or arm64 machine, or use Docker Desktop. Choose a directory for EndPoll and create a config.yaml file before starting the container:

hosts:
  - name: Website
    url: https://example.com
  - name: API
    url: https://api.example.com/health
    conditions:
      code: [200]

Replace these URLs with services reachable from your Docker host. EndPoll checks hosts every 30 seconds by default. The monitoring guide explains intervals, timeouts, and database checks.

2. Start EndPoll

Run this command from the directory containing your config file:

docker run -d \
  --name endpoll \
  --restart unless-stopped \
  -p 8822:8822 \
  -v ./config.yaml:/app/config.yaml \
  -v ./data:/app/data \
  exelban/endpoll:latest

Open http://localhost:8822, or use your server's address if Docker runs on another machine. The data mount keeps your BoltDB monitoring history when the container is replaced.

Images are available on Docker Hub and the GitHub Container Registry. To use the latter, replace the image with ghcr.io/exelban/endpoll:latest. Both registries publish Linux amd64 and arm64 images.

Use Docker Compose

As an alternative to docker run, save this as compose.yaml next to your configuration:

services:
  endpoll:
    image: exelban/endpoll:latest
    container_name: endpoll
    restart: unless-stopped
    ports:
      - "8822:8822"
    volumes:
      - ./config.yaml:/app/config.yaml
      - ./data:/app/data
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8822/healthz"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 5s

Start the service and check its logs:

docker compose up -d
docker compose logs -f endpoll

The /healthz endpoint reports that EndPoll is running. It does not report whether all monitored services are healthy; use the dashboard or /api/hosts for that.

Keep your uptime history

EndPoll uses embedded BoltDB storage by default and shows a 90-day uptime chart. Keep the ./data:/app/data mount when updating or recreating a container. No external database is needed.

For temporary monitoring, set STORAGE_TYPE=memory in the container environment. In-memory history is lost when EndPoll stops.

Protect a private status page

Add basic authentication to config.yaml if the dashboard should require credentials:

ui:
  title: My Status Page
  basicAuth:
    username: admin
    password: replace-with-a-strong-password

This protects the dashboard, JSON API, and Prometheus metrics. The /healthz endpoint stays unauthenticated for health checks. Place EndPoll behind an HTTPS reverse proxy before sending credentials over the internet. If the proxy runs on the same host, bind the container to 127.0.0.1:8822:8822 so it is not exposed directly.

Update your installation

With Docker Compose, pull the image and recreate the service while retaining your mounted config and data:

docker compose pull
docker compose up -d

You can pin an available release tag instead of latest to control upgrades. Review the release notes before updating.

Configure checks and alerts

EndPoll watches the configuration file for changes. Add your services using the HTTP and database monitoring guide, then connect Slack, Telegram, or email notifications to receive status changes.
