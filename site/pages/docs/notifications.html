Configure providers under the top-level notifications section in config.yaml. When combining the examples below, keep one notifications section and place each provider inside it.

EndPoll sends host alerts when status changes after the configured success or failure thresholds. A failed delivery to one channel does not prevent delivery to the other configured channels.

Send uptime alerts to Slack

Create a Slack app with a bot token and the chat:write permission, install it in your workspace, and invite the bot to your monitoring channel. Copy its bot token and use the channel's ID in your config:

notifications:
  slack:
    token: "xoxb-replace-with-your-bot-token"
    channel: "C0123456789"

EndPoll posts through Slack's chat.postMessage API. The configured bot needs access to the destination channel, including membership for private channels.

Send alerts to Telegram

Create a bot with BotFather, then start a conversation with the bot or add it to a group. Set its token and the IDs of the chats that should receive alerts:

notifications:
  telegram:
    token: "123456:replace-with-your-bot-token"
    chatIDs:
      - "111111111"
      - "-1002222222222"

Chat IDs are numeric identifiers, not usernames. For a new bot without a webhook, send it a message and inspect message.chat.id in the getUpdates response using your bot token. Group chat IDs can be negative.

Send email through SMTP

Use the SMTP settings supplied by your email provider. Port 587 is commonly used for STARTTLS; use the host and port your provider specifies.

notifications:
  smtp:
    host: smtp.example.com
    port: 587
    username: monitor@example.com
    password: replace-with-your-smtp-password
    from: endpoll@example.com
    to:
      - admin@example.com
    insecureSkipVerify: false

The provider must allow the configured sender address. Keep certificate verification enabled. Provider credentials belong in the server's configuration file; do not publish them with your status-page content or commit them to a public repository.

Choose notification channels per host

By default, hosts notify all configured providers. Set an alerts list on a host to limit delivery. These values are EndPoll provider names; the email provider is named smtp.

hosts:
  - name: Checkout API
    url: https://api.example.com/health
    alerts: ["slack", "smtp"]
  - name: Personal website
    url: https://example.com
    alerts: ["telegram"]

Each selected provider must also be configured under notifications.

Control repeated alerts

notifications:
  initializationMessage: true
  shutdownMessage: false
  cooldown: 5m

The default cooldown is five minutes between identical notifications for the same host, status, and channel. A recovery has a different status from a downtime alert. Set cooldown: 0 to disable suppression.

Startup messages are enabled by default and can help confirm that a provider is connected. Configuration reloads do not resend them. To verify host alerts, use a test endpoint you control, make it fail, wait for the configured failure threshold, and restore it to check recovery delivery. See the HTTP check example for threshold settings.

Other supported notification providers

EndPoll also supports Discord, Microsoft Teams, Mattermost and Rocket.Chat, Pushover, ntfy, Twilio SMS, BotComm, and generic HTTP webhooks. Provider keys for the alerts list are discord, teams, mattermost, pushover, ntfy, twilio, botcomm, and webhook.

Find their configuration fields in the notification reference on GitHub. For a new installation, start with the Docker setup guide.
